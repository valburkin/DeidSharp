# Testing

| Suite | Where | Runs | Proves |
|---|---|---|---|
| Unit tests | `tests/DeidSharp.Tests` | Always | Each detector, transform and rule on examples and edge cases: formats, Unicode (accents, emoji, combining marks), boundaries, malformed input, failures |
| Property tests | `tests/DeidSharp.Tests/Properties` | Always | Invariants over thousands of generated inputs (CsCheck): no known identifier survives in any template or format, folding never changes length, merged spans are ordered and disjoint, replacement never splits a character, surrogates never equal the original, date shifts are never zero |
| Corpus evaluation | `tests/DeidSharp.Tests/Evaluation` | Always | The deterministic stack's recall on a small annotated synthetic corpus (a regression floor, not a claim about real notes) |
| FHIR tests | `tests/DeidSharp.Tests/Fhir` | Always | A rich fictional bundle (accents, relatives, staff, conditional references, a discharge note, devices, coverage, a contained resource) de-identified in both modes, element by element |
| Evaluation tool | `tests/DeidSharp.Evaluation.Cli.Tests` | Always | The corpus readers (offsets checked against the text, errors that name positions, never text), scoring, publishing, and that the committed results, table and badge agree. Holds the deterministic stack to its recall floor on ASQ-PHI |
| Integration tests | `tests/DeidSharp.IntegrationTests` | With `DEIDSHARP_INTEGRATION=1` | The real Presidio and clinical analyzers through Testcontainers, each stack held to its recall floor on ASQ-PHI |
| Sidecar tests | `sidecar/tests` | `ruff check sidecar && python -m pytest sidecar/tests` (tools in `sidecar/tools/requirements.txt`) | The clinical sidecar's BILOU token grouping and text windowing, that its CPU and GPU locks pin the same packages, and lint |

## Running them

```bash
dotnet test DeidSharp.slnx
```

`dotnet test` runs on Microsoft.Testing.Platform (`global.json`). Do not pass `-nologo`: the test runner rejects it and reports "zero tests ran".

Integration tests need Docker:

```bash
# Stock Presidio (pulled by digest)
DEIDSHARP_INTEGRATION=1 dotnet test tests/DeidSharp.IntegrationTests

# The clinical sidecar too: build it first (downloads torch and the model, a few GB)
docker build -t localhost/deidsharp/clinical-analyzer:local sidecar
DEIDSHARP_INTEGRATION=1 DEIDSHARP_CLINICAL=1 dotnet test tests/DeidSharp.IntegrationTests
```

`DEIDSHARP_PRESIDIO_IMAGE` and `DEIDSHARP_CLINICAL_IMAGE` override the images.

## Continuous integration

`.github/workflows/ci.yml` runs on every push to `main`, on every pull request and once a week:

| Job | What it checks |
|---|---|
| .NET on Linux and Windows | A locked restore (exactly the packages in the lock files, each audited for known vulnerabilities, transitive ones too), a Release build with analyzers and code style as errors, all tests |
| Integration with stock Presidio | The integration tests against the pinned stock Presidio image, the same one `docker-compose.yml` pins (a test keeps the two in step); the clinical sidecar's tests stay opt-in, its image being several GB |
| The sidecar's and the model baselines' Python | The image's lock downloads with every hash matching and holds no package with a known vulnerability (`pip-audit`); the model baselines' lock (`tools/baselines/models`) holds none either, and pins a hash for every package; `ruff check`, `ruff format --check` (with `tools/baselines`), and the tests of the sidecar and of the model baselines' Python |
| Evaluation results (release tags only) | `docs/evaluation/results.json` holds safe-harbor measurements on the nursing notes and ASQ-PHI, and that none of its measurements comes from a later version than the tag, or from code that changed since unless `findings.md` has a release line saying why it stands ([evaluation](evaluation/README.md#before-a-release)) |
| Publish (release tags only) | After every other job passes, packs the five libraries and their symbols and pushes them to nuget.org by Trusted Publishing; the tag must name the packages' version |

`.github/workflows/codeql.yml` scans the C#, the Python and the workflows with CodeQL, once the repository is public (a private one would need GitHub Advanced Security). The weekly runs catch a vulnerability published against a pinned package when nothing changed.

Dependabot (`.github/dependabot.yml`) proposes updates for NuGet, the SDK, the workflow's actions (pinned to commits), the sidecar's check tools, the Docker images and the pinned Presidio image, each release at least five days old. The sidecar's runtime lock is regenerated by hand (`sidecar/README.md`, "Dependencies"); CI's audit says when it holds a vulnerable package. A green run is not enough for an update that can change detection: before merging a new Presidio image or a sidecar runtime package (`presidio-analyzer`, `transformers`, `spacy`…), build the sidecar and run the clinical integration tests by hand, and measure recall on your own sample again.

## Measuring recall on your own data

The tests here use fictional data. Before using DeidSharp on real records, measure it on a sample of them:

1. **Sample** notes from the source you will de-identify, under your data governance. Include every note type (discharge, progress, radiology, messages).
2. **Annotate** every identifier with its category. Two annotators and an adjudication step give a reliable gold standard. The i2b2/n2c2 2014 de-identification guidelines are a good reference for what counts.
3. **Build** an `AnnotatedText` per note. `DetectionEvaluator` gives detectors the text only, so the known-identifier detector finds nothing: the result is a floor for use with the record's identifiers.
4. **Run** your detector stack through `DetectionEvaluator`. Report recall, character recall and precision, and recall per category. `tools/DeidSharp.Evaluation.Cli` does this for the corpora it can read ([evaluation](evaluation/README.md)); a reader for your own format is one class.
5. **Read the misses.** A missed name is a leak; look at each one and decide whether a detector, a pattern, the known identifiers or the stack needs to change.
6. **Repeat** whenever the source system, the note types, the detectors or DeidSharp change.

Published de-identification systems report recall on i2b2/n2c2 in the high 90s percent; clinical NER alone is lower on text unlike its training data. Your own number is the one that matters.

## Adding a test case

- A new format or identifier shape: add an `InlineData` row to `PatternPhiDetectorTests` (positive) and, if it risks false positives, a negative case to `Leaves_ordinary_clinical_text_alone`.
- A new structured element: add it to `rich-patient-bundle.json` (via a test that builds it) and assert on it in the FHIR tests.
- A missed identifier from real data: reduce it to a fictional example of the same shape and add it as a regression test. Never commit real patient text.
