# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this is

DeidSharp de-identifies health data for .NET: HIPAA Safe Harbor transforms, keyed pseudonyms, stackable PHI detectors for free text, a deterministic leak guard, re-identification risk metrics and detector evaluation, with FHIR R4 supported directly. It ships as libraries (`DeidSharp`, `DeidSharp.Fhir`, `DeidSharp.Gazetteer`, `DeidSharp.Llm`, `DeidSharp.Presidio`), with the clinical sidecar and the evaluation tool that measured them. See [README.md](README.md) and [docs/](docs/).
It is research-grade software, and the public companion to a paper: readers clone it to reproduce the measurements. Everything in it, history included, must be fit to publish: no references to private projects, machines or people, no internal planning notes, and no real patient data.

## Rule that matters most: PHI never leaks

Every input may be PHI. Each change keeps these guarantees, and so do its tests:

- **Nothing quotes the input.** Exceptions, log messages, spans, findings and reports carry only positions, categories and paths. Name an invalid entry by its position (`ageBandPaths[2]`), never by its value. Never log a request body, and never wrap a third-party message that may quote the input (the Firely parser's, for example).
- **Fail closed.** A detector that fails throws `PhiDetectionException`, and the whole run stops. It never reads as "nothing found". Leftover PHI in the output throws `ResidualPhiException`. A null or missing input is refused; it is never scanned as clean.
- **The leak guard stays deterministic.** `LeakScanner` uses the known-identifier and pattern detectors only, whatever the free-text stack holds, so the check never shares a model's failure modes.
- **Keys stay server-side.** Pseudonym keys come from configuration or a secret store, never from a request, and `PseudonymKey` never exposes its bytes.
- **Recall first.** A span that any detector reports is replaced. Raise a threshold only with evaluation results that justify the lost recall.

[docs/threat-model.md](docs/threat-model.md) is the contract. If a change alters what it says, update it in the same change.

## Commands

```bash
dotnet build DeidSharp.slnx
dotnet test DeidSharp.slnx                           # never add -nologo (see below)
DEIDSHARP_INTEGRATION=1 dotnet test DeidSharp.slnx   # also the stock Presidio container (Docker)
ruff check sidecar tools/baselines && python -m pytest sidecar/tests # the sidecar and Philter's runner (tools: sidecar/tools/requirements.txt)
dotnet run --project tools/DeidSharp.Evaluation.Cli -c Release -- --corpus asq-phi   # recall on a corpus (docs/evaluation)
```

Tests run on Microsoft.Testing.Platform (`global.json`). `dotnet test` forwards unknown flags to the test app, so `-nologo` makes it fail with exit code 5 and "Zero tests ran". That output looks like a broken environment, but it isn't.

ReSharper-clean is part of done. Check with `jb inspectcode DeidSharp.slnx --severity=HINT --format=Sarif --caches-home=<fresh folder>`; a reused cache ignores `.editorconfig` changes. Fix suggestions in changed code. Leave a note only where a hint flags public API as unused, and say why.

## Layout

- `src/DeidSharp/`: the core. No package dependencies, on purpose: every caller loads it, and the deterministic layers must run anywhere. Folders are namespaces: `Detection` (with `Known/` and `Patterns/`), `Text`, `Structured`, `Dates`, `Pseudonymization`, `Verification`, `Risk`, `Evaluation`, `Diagnostics` (metrics and traces, which carry names, categories and counts only).
- `src/DeidSharp.Fhir/`: FHIR R4 on Firely. It holds the rule chain (`Rules/`), reference rewriting and the FHIR output check.
- `src/DeidSharp.Gazetteer/`: a deterministic detector for names and places, with its public-domain lists embedded (`Data/`, regenerated by `tools/gazetteer/build.cs`; `Data/SOURCES.md` gives sources and licenses).
- `src/DeidSharp.Llm/`: a detector that asks a language model through Microsoft.Extensions.AI's `IChatClient` (meant for a local model); never part of the leak guard.
- `src/DeidSharp.Presidio/`: a detector backed by a Presidio analyzer over HTTP.
- `sidecar/`: the clinical analyzer (Presidio with a transformer NER model, run offline).
- `tools/DeidSharp.Evaluation.Cli/`: measures detector stacks on annotated corpora (PhysioNet's nursing notes, the bundled ASQ-PHI copy) and publishes the numbers to `docs/evaluation`. Not a package. It also holds the experiments that didn't earn a place in the libraries (`RepeatedNameDetector`, `TfIdfExampleRetriever`, the self-check second opinion), so every finding stays reproducible.
- `tools/baselines/`: what runs the other tools the evaluation compares with (Philter's image, a converter of their output to the tool's TSV). Neither tool is vendored.
- `tests/`: `DeidSharp.Tests` (unit, property and corpus tests, mirroring `src/`), `DeidSharp.Evaluation.Cli.Tests` (the evaluation tool, mirroring `tools/`) and `DeidSharp.IntegrationTests` (real sidecars, opt-in). Read the tests as the specification.

## Code conventions

- **Build gates.** Analyzers run at `10.0-recommended` (named, so a new SDK cannot fail an unchanged build) with code style enforced, and warnings fail the build. Turn off a rule that doesn't fit in `.editorconfig`, with a reason; never suppress one ad hoc. Package versions live only in `Directory.Packages.props`; commit the `packages.lock.json` files a restore updates. Library code awaits with `ConfigureAwait(false)` (CA2007); the tools and the tests are exempt.
- **SOLID.** Check new and changed code against all five principles and fix violations as part of the work. Tools (`Program.cs`) and tests are not exempt.
  - Add variation as a new strategy class or a table row (a detector, a FHIR rule, a pattern), not as a new branch in existing code.
  - Depend on abstractions at external boundaries (detectors, HTTP).
  - The outermost layer may use concrete library services without inventing interfaces that have only one implementation. Say so when you make that call.
- **The libraries ship what is recommended.** A published package holds only what a recommended stack uses, or an opt-in whose trade-off is measured and documented. An experiment lives in the evaluation tool until a finding justifies it.
- **Detectors stay pluggable.** Each one is an `IPhiDetector` that can be stacked in a `CompositePhiDetector`. Adding a provider never changes the existing ones.
- **One main type per file**, named after it. A small record or enum that only makes sense with its owner (its parts, result or settings) shares the owner's file. Shared concepts, interfaces, implementations, exceptions and options get their own files. Namespaces follow folders (IDE0130), and `tests/` mirrors `src/` and `tools/`.
- **Design pattern comments.** Wherever code uses a design pattern, add a dedicated comment above the type's XML doc, with a blank line between them, written for a junior who learns by reading the code:
  ```csharp
  // Design pattern: <Name>.
  // The pattern: <general one- or two-line definition>.
  // Here: <how and why it's used in this code>.
  ```
  - Each block stands alone. Never write "see X"; repeat the definition, using the same wording for the same pattern everywhere.
  - Test doubles get `Test Double (Stub/Fake/Spy)`.
  - If a name suggests a pattern the code doesn't implement, say so.
- **Public API.** The packages' public types are a contract for every caller: extend them, don't break them, and list a breaking change in the CHANGELOG.
- **Options** validate their own values. A bad value throws; it never falls back to a default silently.
- **Docs travel with code.** The README examples are run as tests (`ReadmeExamplesTests`), so keep them in step. [docs/safe-harbor.md](docs/safe-harbor.md) lists, element by element, how each of the 18 identifiers is handled.
- **Language and comments.** American English everywhere: code, comments, docs and commit messages. Comments explain why, in the density and voice of the surrounding code.

## Data

- Fixtures and test corpora are fictional. Never add real patient data, and never commit sidecar model downloads or generated output.
- Credentialed corpora (PhysioNet) stay on the maintainer's machine under their data use agreement: never commit them or the evaluation tool's `--misses` and `--false-positives` files, and never read them into an AI assistant. Only `docs/evaluation`'s counts and rates are published.
- Log every measurement as the next finding in [docs/evaluation/findings.md](docs/evaluation/findings.md), in the same commit, with its date, corpus and half, and the command's settings, so [REPRODUCING.md](REPRODUCING.md) can rerun it.
- Tune on the tuning half only. The reporting half is for numbers that get published; a new choice needs the tuning half or new data.
- No claims of HIPAA compliance or certification. DeidSharp removes what its rules and detectors find; the README and the threat model say what it does not guarantee.
